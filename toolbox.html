Three weeks, ten sessions. One API I built and everything I took with me.

Peptide
Data API

20 sources that had never talked to each other. Now they answer the same question.

An API is a hatch in the wall. You send in a question, you get an answer back, and you never have to see the kitchen. This kitchen is 20 websites I scraped.

I scraped the 10 biggest research platforms for peptides and the 10 biggest forums where people actually discuss them. The raw data was cleaned, structured per peptide and put behind an API. So instead of opening 20 tabs and searching in each one, you ask a single question and get everything at once.

It is the same thing the course was about: fetch, find, store. Only at scale.

1
Fetch

Node + cheerio and Agent Reach scrape the pages. Robots.txt is checked first. Raw data is saved per source.

2
Find

Every text is tagged with peptide name, source, date and type: study or discussion.

3
Store

Everything lands in a JSON layer, one object per peptide.

4
Answer

The API takes a peptide name and sends back studies, forum threads and what gets mentioned the most.

research platforms

    forums and communities

      What does the research say?

      Studies and abstracts per peptide, collected from the platforms. What has actually been tested, on what, and when.

      "Are there studies on BPC-157 and tendons?"

      What do people say?

      The forum threads show what users talk about, what they ask and what keeps coming back. That is often where the next question for the research is born.

      "Which peptides are discussed the most right now?"

      Where is the gap?

      When the forums talk a lot and the research says little, or the other way around, there is a content hole. That is where an article, a post or a product has the biggest effect.

      "Which peptide is the most talked about but the least studied?"

      This is what we can do

      Four clusters from the learning objectives.

      A

      A data-driven way of working

      • Measure first, guess later. Decisions from data, not from gut feeling.
      • Hypothesis → test → evaluate.
      • Structured prompts for an LLM: context, goal, way of working.
      • Data quality decides the conclusion.
      B

      Measuring and collecting

      • GTM + GA4: tags, triggers, variables.
      • Collect via APIs, datasets and scraping.
      • Knowing what you measure, and why.
      • Not getting stuck just collecting data.
      C

      Analysing and processing

      • Visualise in Chart.js and Data Studio.
      • Scraping → Google Sheets → insights.
      • GA4 DebugView and real-time reports.
      • AI tools in VS Code speed up the analysis.
      D

      Finding growth and recommending

      • How you collect data, and what the tools do.
      • Data + visualisation → find the optimisations.
      • Seeing which audiences you should aim at.
      • Making the decisions that actually create growth easier.
