2.3 Careful now 30 minutes

Read a value stored earlier in the visit

What this page is for

The dataLayer is wiped by every page load. This page shows you where to put something that has to survive the visitor walking to the next page.

You will build:

  • A Custom JavaScript variable that reads sessionStorage
  • A tag that reports the stored value on every page
  • The landing-page capture pattern used for campaigns

Three places to keep things

sessionStorageGone when the tab closes. Per tab, not per browser. Use for "this visit".
localStorageSurvives restarts, indefinitely. Use for a returning-visitor flag.
CookiesSent to the server on every request, with an expiry you set. What GA4 itself uses.

  1. Type a campaign name below and press Save to sessionStorage.

  2. Go to exercise 2.1.

  3. Come back with the browser's back button.

  4. Press Read it back. The value survived. The dataLayer did not.

Step 2 Build the Custom JavaScript variable

  1. Variables › New › Custom JavaScript.

  2. Paste this. It must be an anonymous function that returns a value.

    function() {
  try {
    return window.sessionStorage.getItem('course_campaign') || '(not set)';
  } catch (e) {
    // Private mode throws here rather than returning null.
    return '(unavailable)';
  }
}

  3. Name it js — stored campaign. Save.

Two things break this variable

Forgetting return. The variable will be empty and there is no error message.

Forgetting try / catch. Merely touching sessionStorage can throw in a private window, and a Custom JavaScript variable that throws can take the whole tag with it.

Step 3 Build a tag that reads it everywhere

  1. Tags › New › Custom HTML:

    <script>
  console.log("Campaign in storage:", {{js — stored campaign}});
</script>

  2. Attach the All Pages trigger. Save.

  3. Preview. Store a value here, then navigate to any other exercise page.

Step 4 Do it the way a real site does

The real pattern: on every page load, if there is a utm_source in the URL, write it to storage. Then read from storage everywhere.

  1. Open this page with ?utm_source=classroom.

  2. Check the readout. The value was captured from the URL and stored.

  3. Navigate to another exercise page. Your tag still reports classroom.

What you should see

  • js — stored campaign appears in the Variables tab on every event, on every page.
  • It keeps its value after you navigate to a different page in the course.
  • Running sessionStorage.getItem('course_campaign') in the console returns the same string.
  • Opening a course page in a new tab shows nothing — sessionStorage is per tab.

If it does not work

  • The variable is always empty. You left out return.
  • It works for you and not for a classmate. They are in a private window. That is what the catch branch is for.
  • The value is wrong or old. Storage has no expiry. A campaign written on Monday is still there on Friday if the tab stayed open. Store a timestamp next to it.
  • The value is missing in a new tab. Expected. Use localStorage or a cookie if you need it across tabs.

What not to store

A campaign name is fine. An email address, a customer ID or anything identifying belongs behind consent and in a cookie with a deliberate expiry, not in localStorage forever.

Go further

  1. Change the variable to read localStorage. Close the browser completely, reopen this page, and check whether the value survived. Which would you use for a "first visit date"?
  2. Store an object instead of a string. Storage only holds strings, so you need JSON.stringify going in and JSON.parse coming out — with a try / catch around the parse.
  3. Write a variable that returns how many minutes ago the campaign was stored.
