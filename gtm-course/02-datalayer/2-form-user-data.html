2.2 Careful now 35 minutes

Send form data, and hash what is personal

What this page is for

This page has a lead form. When you submit it, the email address is hashed in your browser and only the hash goes into the dataLayer. You will read that hash in Tag Manager.

You will build:

  • Data Layer Variables that reach into a nested object with dots
  • A tag that reads the hashed email
  • Proof that normalising the address before hashing is not optional

Why hashing at all

Ad platforms want to know the person who filled in your form is the person who clicked an ad last week. A SHA-256 hash lets them check that without you sending a plain email address. They hash their copy the same way and compare. It only works if both sides clean the address identically first.

Step 1 Submit the form

Use a made-up address. Nothing leaves your browser — the hash is calculated locally.

Lead form

Fill it in and submit.

What the page does on submit

// 1. Normalise: trim, lowercase. Google does the same on their side.
const clean = email.trim().toLowerCase();

// 2. Hash with the browser's built-in crypto.
async function sha256(value) {
  const bytes  = new TextEncoder().encode(value);
  const digest = await crypto.subtle.digest('SHA-256', bytes);
  return Array.from(new Uint8Array(digest))
    .map(b => b.toString(16).padStart(2, '0'))
    .join('');
}

// 3. Push the hash — never the address itself.
dataLayer.push({
  event: 'generate_lead',
  user_data: {
    sha256_email_address: await sha256(clean),
    address: { first_name: 'anna', country: 'SE' }
  }
});

Step 2 Build a Data Layer Variable for a nested value

The hash is not at the top level. It is inside user_data. Reach into an object with dots.

  1. Variables › New › Data Layer Variable.

  2. Data Layer Variable Nameuser_data.sha256_email_address
    Data Layer VersionVersion 2
    Namedlv — user_data.sha256_email_address

  3. Build a second one for user_data.address.first_name. The dots keep working however deep the object goes.

Step 3 Build the trigger and tag

  1. Triggers › New › Custom Event, event name generate_lead.

  2. Tags › New › Custom HTML:

    <script>
  console.log("Lead:", {{dlv — user_data.sha256_email_address}});
</script>

  3. Attach the trigger. Save. Preview.

Step 4 Prove that normalising matters

  1. Submit the form with anna@example.com. Note the first eight characters of the hash.

  2. Submit again with   Anna@Example.COM   — spaces and capitals included.

  3. Compare the two hashes.

What you should see

  • The hash is 64 hexadecimal characters, always, no matter how long the email was.
  • Both submissions above produce the same hash. That is the normalisation working.
  • anna@example.com always hashes to f7d54c22dda5b1780276601cd005909b70543fc4a6ba72d735b4cb9bbb611f01. Everyone in the room gets that string.
  • In Tag Assistant, dlv — user_data.sha256_email_address shows the same value.

If it does not work

  • The variable is empty. A missing or extra dot in the variable name. Compare it against the object in the panel, character by character.
  • Your hash is shorter than 64 characters, or has letters past f. That is not SHA-256.
  • The page says crypto.subtle is unavailable. It only exists on HTTPS. A hashing script that works in production can fail silently on an http:// staging server.

Read this part twice

  • A hash is not anonymisation. Under GDPR a hashed email is still personal data — whoever holds the original can reproduce the hash and match it. Hashing changes what you may send to an ad platform. It does not remove your need for a legal basis or consent.
  • Never push the raw address alongside the hash. Once a plain email is in the dataLayer, every tag in the container can read it, including third-party tags you did not write. Hash at the source.
  • The bit-shift "hash" in old tutorials is not a hash. Short loops multiplying character codes produce a number with a handful of digits. They collide constantly. If you inherit code doing this, replace it.
