Read a single parameter

What this page is for

This page reads a name parameter out of its own address and changes its heading. You will read the same parameter from Tag Manager.

You will build:

  • A URL Variable set to Component Type Query
  • A trigger that only fires when the parameter is actually there

Step 1 Load the page with a parameter

Click the links. Each one reloads this page with a different query string. Watch the heading above and the box below.

Four ways to arrive

?name=Anna ?name=Erik Svensson ?name= (empty) no parameter

What the page does

const params = new URLSearchParams(window.location.search);
const name   = params.get('name');   // null if absent, "" if present but empty

if (name) {
  document.getElementById('heading').textContent = 'Hello, ' + name;
  dataLayer.push({ event: 'parameter_loaded', visitor_name: name });
}

Step 2 Build the URL Variable

  1. Variables › New › URL.

  2. Component TypeQuery
    Query Keyname
    Set Default ValueOn, (not set)
    Nameurl — name

  3. Save. No JavaScript, no developer, no dataLayer. This works on any page of any site your container is on.

Step 3 Build a tag on page load

  1. Tags › New › Custom HTML:

    <script>
  console.log("Name parameter:", {{url — name}});
</script>

  2. Attach the All Pages trigger. Save. Preview with ?name=Anna.

Step 4 Only fire when there is something to report

Logging (not set) on every page in the world is noise.

  1. Triggers › New › Page View. Choose Some Page Views.

  2. Conditionurl — name  does not equal  (not set)
    NamePage View — name parameter present

  3. Swap this trigger onto your tag, replacing All Pages. Save and preview again.

What you should see

  • With ?name=Anna: the variable shows Anna and the tag fires.
  • With no parameter: the variable shows (not set) and the tag is under Tags Not Fired.
  • With ?name=Erik%20Svensson: the variable shows Erik Svensson. Tag Manager decoded the %20 for you.
  • With ?name=: the variable shows an empty string, not (not set) — and the tag fires anyway.

If it does not work

  • The variable is empty on a URL that clearly has the parameter. Component Type is not set to Query, or the Query Key is misspelled.
  • ?name= slips past your condition. Present-but-empty is not missing, so the default never applies. Use does not match RegEx ^$|\(not set\) instead.
  • ?Name=Anna returns nothing. Parameter names are case sensitive. Tell whoever builds your campaign links.

Never put anything private in a URL

Query strings end up in browser history, server logs, the referrer header sent to other sites, and every analytics report you own. An email address in a ?email= parameter is a data breach with extra steps.

Go further

  1. Build a second URL Variable with Component Type Path and see what it returns here.
  2. Add the built-in {{Page URL}} variable to the tag so you can compare the two.
  3. Make the tag also push a dataLayer event, so the value is available to other tags.
