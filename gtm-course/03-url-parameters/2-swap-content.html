3.2 Getting real 25 minutes

Change the page from the URL

What this page is for

This is a landing page whose headline matches the ad that sent you. You will make Tag Manager do the rewriting — the first time you use it to change a page rather than watch one.

You will build:

  • A URL Variable for a content parameter
  • A Custom HTML tag on a DOM Ready trigger that rewrites the headline
  • A dataLayer push recording which variant was shown

Step 1 Arrive from four different ads

The landing page

The two lines in the box get replaced.

Everything you need to run better campaigns

Step 2 Build the URL Variable

  1. Variables › New › URL.

  2. Component TypeQuery
    Query Keycontent
    Set Default ValueOn, (not set)
    Nameurl — content

Step 3 Build the trigger

  1. Triggers › New › Page View › DOM Ready.

  2. Choose Some DOM Ready Events.

  3. Conditionurl — content does not equal (not set)
    NameDOM Ready — content parameter present

  4. Save.

Why DOM Ready and not Page View

A Page View trigger fires while the browser is still reading the HTML. The headline may not exist yet, and your tag would find nothing. DOM Ready means the page structure is complete.

Step 4 Build the tag

  1. Tags › New › Custom HTML:

    <script>
  (function() {
    var headline = document.getElementById('dynamic-headline');
    if (!headline) { return; }          // the element may not exist

    headline.textContent = {{url — content}};

    dataLayer.push({
      event: 'content_variant_shown',
      content_variant: {{url — content}}
    });
  })();
</script>

  2. Attach the DOM Ready trigger. Save.

  3. Preview, then click Ad A above.

Two habits in that snippet

It is wrapped in a function, so its variables cannot collide with the website's own.

It checks the element exists before touching it. A tag that throws an error can stop later tags in the same container from running.

Step 5 Track the variant

  1. Build a Data Layer Variable for content_variant.

  2. Build a Custom Event trigger for content_variant_shown.

  3. Now every later event can be segmented by which headline the visitor saw. That was the point.

What you should see

  • With ?content=Save%20four%20hours%20a%20week: the headline changes.
  • Tag Assistant shows a DOM Ready event with your tag fired.
  • Then a content_variant_shown event carrying the text.
  • With no parameter: the default headline stays and no tag fires.

If it does not work

  • The headline does not change. The trigger is a Page View, not DOM Ready. The element did not exist yet.
  • The tag fires on every visit. The condition is missing, or you left the trigger on All DOM Ready Events.
  • Never use innerHTML here. The text comes straight from the address bar. With innerHTML, anyone can send a link that injects working HTML and script into your page. Use textContent.
  • Visitors see the old headline first. That is flicker, and it is real. Serious personalisation and A/B testing is done on the server or in the page's own code for this reason.

Go further

  1. Extend the tag to replace the paragraph too, from a second parameter ?sub=.
  2. Use a Lookup Table so the URL carries a short code — ?content=a — and the table holds the real text. Cleaner links. What did you lose?
  3. Find where GA4 lets you exclude a query parameter from reports, and exclude content.
