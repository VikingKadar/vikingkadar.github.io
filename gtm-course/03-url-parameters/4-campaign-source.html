3.4 Getting real 30 minutes

Track where a visitor came from

What this page is for

This page is a campaign landing page with a link builder on it. You will build a real campaign URL, land on this page with it, and read every part of it in Tag Manager.

You will build:

  • Three URL Variables for the UTM parameters
  • A tag that only fires on campaign landings
  • A comparison against what GA4 already collects on its own

The five parameters everyone uses

utm_sourceWhere the click came from. newsletter, facebook. Required.
utm_mediumThe kind of channel. email, cpc, social. Required, and the one most often wrong.
utm_campaignWhich campaign. spring-sale-2026. Required.
utm_contentWhich specific ad or link. Optional.
utm_termThe keyword, for paid search. Optional, largely historical.

Step 1 Build a campaign link and land on it

Campaign link builder

Fill it in. It builds a real URL back to this page and opens it.

Arrive with nothing

Your campaign URL will appear here.

Step 2 Build three URL Variables

One each for utm_source, utm_medium and utm_campaign. All the same shape:

TypeURL
Component TypeQuery
Query Keythe parameter name
Set Default ValueOn, (direct)
Nameurl — utm_source, and so on

Use (direct) rather than (not set) as the default. A visit with no campaign parameters genuinely is a direct visit, and reports read better for it.

Step 3 Fire a tag on campaign landings only

  1. Triggers › New › Page View, Some Page Views.

  2. Condition: url — utm_source does not equal (direct).

  3. Tags › New › Custom HTML:

    <script>
  console.log("Campaign landing", {
    source:   {{url — utm_source}},
    medium:   {{url — utm_medium}},
    campaign: {{url — utm_campaign}}
  });
</script>

  4. Attach the trigger. Save. Preview and land with a campaign URL.

Step 4 Compare with what GA4 already knows

  1. If you have a GA4 tag in your container, open the Realtime report.

  2. Land on this page with a campaign URL.

  3. Look at source, medium and campaign in Realtime. They are already there.

You just built variables for values GA4 reads by itself. Worth knowing before you build them again next month. They start earning their keep the moment you send data anywhere other than GA4.

What you should see

  • Landing with all three parameters: all three variables show their values and the tag fires.
  • The panel shows a campaign_landing event.
  • Landing with no parameters: all three show (direct) and the tag does not fire.
  • GA4 Realtime shows the same source, medium and campaign without any variable of yours.

If it does not work

  • Two rows in your report for the same campaign. Newsletter and newsletter are different strings. Pick lowercase, write it down, make everyone follow it.
  • Traffic lands in "Unassigned". utm_medium is free text, but only about eight values map to GA4's default channel groups: email, cpc, organic, social, referral, affiliate, display. Invent one and you lose the channel.
  • Sessions restart in the middle of a visit. You tagged an internal link. Never put UTM parameters on a link from your own site to your own site — it throws away the real source.
  • A campaign shows almost no traffic. Some email clients, link shorteners and in-app browsers strip query strings. Test the real link from the real client before blaming the tracking.

Parameters only exist on the landing page

Click one link and they are gone, so a purchase three pages later has no campaign attached. Combine this with exercise 2.3: write utm_source to sessionStorage on arrival, read it from storage everywhere else. GA4 does its own version with a cookie, which is why you usually do not have to.

Go further

  1. Build a Lookup Table turning utm_medium into a friendly channel name — cpc to Paid search, email to Newsletter — with a default of Other.
  2. Store the campaign in sessionStorage on arrival, then prove on another exercise page that you can still read it.
  3. Write down the naming convention your class will use for source, medium and campaign. Actually write it down — that document is the most valuable thing in most analytics setups.
