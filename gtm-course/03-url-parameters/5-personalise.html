3.5 Getting real 25 minutes

Two parameters, one page state

What this page is for

Two parameters — theme and user — decide how the box below looks and what it says. You will report that combined state to Tag Manager as one clean value.

You will build:

  • Two URL Variables
  • A Lookup Table translating theme into a readable label
  • A tag that reports both, with sensible defaults when nothing was supplied

Step 1 Try the combinations

Personalised panel

Welcome, Guest

Theme: light

dark + Anna light + Erik dark, no user theme=neon (invalid) nothing

The toggle button rebuilds the URL and reloads. That is deliberate: the page state is always readable from the address, so it can be shared, bookmarked, and — the part that matters here — read by Tag Manager on page load.

Step 2 Build two URL Variables

url — themeURL, Query, key theme, default light
url — userURL, Query, key user, default Guest

The defaults here are not (not set). They are the values the page actually uses when the parameter is absent, so your variables match what the visitor really saw.

Step 3 Build the Lookup Table

  1. Variables › New › Lookup Table.

  2. Input Variable{{url — theme}}
    lightLight mode
    darkDark mode
    Set Default ValueOn, Unsupported theme
    Namelookup — theme label

  3. Save.

The default row is doing real work. ?theme=neon is a link somebody will send you, and without a default you would report an empty theme instead of a broken one.

Step 4 Build the trigger and tag

  1. Triggers › New › Custom Event, event name page_personalised.

  2. Tags › New › Custom HTML:

    <script>
  console.log("Page state", {
    theme:      {{url — theme}},
    theme_label: {{lookup — theme label}},
    user:       {{url — user}}
  });
</script>

  3. Attach the trigger. Save. Preview and click through the links above.

What you should see

  • ?theme=dark&user=Anna: the box turns dark, and the variables read dark, Dark mode, Anna.
  • ?theme=dark with no user: url — user falls back to Guest, matching what the box says.
  • ?theme=neon: the box stays light, and lookup — theme label reads Unsupported theme.
  • No parameters at all: light, Light mode, Guest. The tag still fires — the page still has a state.

If it does not work

  • The lookup always returns the default. Lookup Tables are case sensitive. Dark is not dark. Add both rows, or use a RegEx Table.
  • The user name arrives with %20 in it. Tag Manager decodes it for you; your own JavaScript does not unless you call decodeURIComponent().
  • Your variable says one thing and the page shows another. Your default does not match the page's default. Set the variable defaults to the values the page actually falls back to.

A name in a URL is a name in your reports

?user=Anna is fine in a classroom. On a live site the same pattern puts real names into page paths, referrer headers and every report you own. Personalise from a session cookie or a login, not from the address bar.

Go further

  1. Add a third state, ?density=compact, and fold it into the same event.
  2. Replace the Lookup Table with a RegEx Table that accepts dark, Dark and DARK.
  3. Store the theme in localStorage so it survives without a parameter, then compare which source your variable should trust first.
