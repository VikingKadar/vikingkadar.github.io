Scroll depth and element visibility

What this page is for

This page is long, and it has a box near the bottom that only appears when you press a button. You will fire tags off both facts, without anyone clicking anything you are tracking.

You will build:

  • A Scroll Depth trigger with four thresholds
  • An Element Visibility trigger with Observe DOM changes on
  • A tag that reports which threshold was crossed

Step 1 Switch on the scroll variables

  1. Variables › Configure.

  2. Under Scrolling, tick Scroll Depth Threshold, Scroll Depth Units and Scroll Direction.

Step 2 Build the Scroll Depth trigger

  1. Triggers › New › Scroll Depth.

  2. Tick Vertical Scroll Depths and choose Percentages.

  3. Percentages25,50,75,90
    Fires onAll Pages
    NameScroll — vertical percentages

  4. Save. One trigger covers all four thresholds.

Step 3 Build the tag

  1. Tags › New › Custom HTML:

    <script>
  console.log("Scrolled to", {{Scroll Depth Threshold}} + "%");
</script>

  2. Attach the scroll trigger. Save.

Step 4 Build the Element Visibility trigger

Near the bottom of this page is a box with the id thank-you. It does not exist when the page loads.

  1. Triggers › New › Element Visibility.

  2. Selection MethodID
    Element IDthank-you
    When to fireOnce per page
    Minimum Percent Visible50
    Observe DOM changesOn
    NameVisibility — thank you box

  3. Save. Build a second Custom HTML tag on this trigger that logs "Thank you shown".

  4. Press Preview and connect to this page.

  5. Scroll slowly to the bottom, then press the reveal button.

Observe DOM changes is not optional here

Without it, Tag Manager looks for the element once, does not find it, and gives up. The box is added after page load, so the trigger would never fire.

What you should see

  • Four separate Scroll Depth events in Tag Assistant as you scroll: 25, 50, 75, 90.
  • Clicking each one and opening Variables shows Scroll Depth Threshold changing.
  • One Element Visibility event when you reveal the box — and only one, even if you scroll it off screen and back.
  • Two different messages in the console.

If it does not work

  • All four scroll thresholds fire at once on load. The whole page fits on your screen, so you are already at the bottom. Make the window smaller, or check on a phone.
  • The visibility trigger never fires. Observe DOM changes is off, or the Minimum Percent Visible is higher than the part of the box actually on screen.
  • The visibility trigger fires many times. You set Once per element or Every time instead of Once per page.
  • Scroll Depth Threshold is blank in the tag. The built-in variable is not enabled. Go back to Step 1.

What these numbers are worth

A visitor who reaches 90% may have read every word, or flicked past on a phone in one thumb movement. Scroll depth is a weak signal. Use it where nothing better exists, and do not build a KPI on it.

Element Visibility is the stronger of the two, and the one you will use most: a thank-you message on a form you do not control, a cookie banner appearing, a product list scrolling into view.

What Module 1 covered

A tag is code Tag Manager runs for you. Every tag in this module was a Custom HTML tag that wrote to the console. On a real site it would be a GA4 event tag or an advertising pixel.

A trigger is the condition. You have built five kinds: All Pages, a filtered Click trigger, a Form Submission trigger with validation, a Scroll Depth trigger, and an Element Visibility trigger.

A variable is a value filled in when the tag fires. Four types: Constant, Data Layer Variable, DOM Element, Lookup Table.

What Module 1 did not cover

  • Consent. On a European site, no tag should fire before the visitor agrees. Tag Manager has a whole consent system for it.
  • Server-side tagging, where the container runs on your server rather than in the browser.
  • Publishing discipline: version names, container notes, and the fact that Submit is what makes anything real.

One habit worth starting today

Name things. A container with tags called GA4 — purchase and Meta — pageview can be understood in ten minutes. A container with Tag 1, Untitled Tag and test copy 2 gets thrown away and rebuilt.

Pick a convention on day one: platform, em dash, event name. Use a type prefix for variables and triggers, the way this course does: dlv —, lookup —, url —.
