1.4 Getting real 30 minutes

Four variables, four jobs

What this page is for

This page is a pricing table. You will build one of each variable type Tag Manager offers, and get all four to appear in a single tag.

You will build:

  • A Constant — a value you type once
  • A Data Layer Variable — a value the page gives you
  • A DOM Element variable — a value scraped off the page
  • A Lookup Table — a value translated into another value

A variable is a named box. You write {{Plan name}} in a tag; Tag Manager puts Pro in its place when the tag fires. The four types differ only in where the value comes from.

Step 1 Click the plan buttons

Pick a plan. Two things happen: the price on the page changes, and an event goes into the dataLayer. Watch both.

Pricing demo

The price sits in an element with the id plan-price. The plan name goes into the dataLayer.

Selected plan: none · Price: — SEK / month

Step 2 Build the Constant

  1. Go to Variables › User-Defined Variables › New.

  2. Choose Constant.

  3. ValueSEK
    Nameconst — currency

  4. Save.

Use it for: measurement IDs, currency codes, anything you would otherwise retype in nine tags.

Step 3 Build the Data Layer Variable

Press a plan button and look at the panel. The pushed object has a key called plan_name. Ask for it by name.

  1. Variables › New › Data Layer Variable.

  2. Data Layer Variable Nameplan_name
    Data Layer VersionVersion 2
    Set Default ValueOn, (not set)
    Namedlv — plan_name

  3. Save.

The name must match the key exactly, including case. For a value inside an object, use dots: ecommerce.items.0.item_name.

Step 4 Build the DOM Element variable

Nobody put the price in the dataLayer, so take it off the page instead.

  1. Variables › New › DOM Element.

  2. Selection MethodID
    Element IDplan-price
    Attribute Nameleave empty
    Namedom — plan price

  3. Save.

Empty Attribute Name gives you the element's text. Fill it in with data-price and you get that attribute instead.

Step 5 Build the Lookup Table

Finance calls the plans by internal codes. Translate once, here, instead of in every tag.

  1. Variables › New › Lookup Table.

  2. Input Variable{{dlv — plan_name}}
    BasicP-100
    ProP-200
    EnterpriseP-900
    Set Default ValueOn, P-000
    Namelookup — plan code

  3. Save.

Step 6 Use all four in one tag

  1. Make a trigger: Triggers › New › Custom Event, event name select_plan. Name it Custom Event — select_plan.

  2. Make a tag: Tags › New › Custom HTML.

    <script>
  console.log("Plan selected", {
    plan:     {{dlv — plan_name}},
    code:     {{lookup — plan code}},
    price:    {{dom — plan price}},
    currency: {{const — currency}}
  });
</script>

  3. Attach the trigger. Save.

  4. Press Preview, connect to this page, and click Pro.

What you should see

  • Tag Assistant shows a select_plan event with your tag under Tags Fired.
  • On that event, the Variables tab shows exactly this:
dlv — plan_namePro
lookup — plan codeP-200
dom — plan price299
const — currencySEK

If it does not work

  • dom — plan price is empty. The variable reads the page at the moment the tag fires. If the tag fires before the price is written, you get nothing. This is why scraped values are unreliable.
  • dlv — plan_name keeps an old value. The dataLayer remembers. A key keeps its last value until something overwrites it. Expect this and check it.
  • lookup — plan code returns P-000. The input did not match a row. Lookup Tables are case sensitive: pro is not Pro.
  • The tag does not fire at all. The Custom Event name must be select_plan exactly. Check for a trailing space.

Which type to reach for

In this order: Constant if you know the value, Data Layer Variable if the site publishes it, DOM Element only if there is no other way. The further down the list you go, the more likely a designer breaks your tracking without knowing.

Go further

  1. Change the DOM Element variable to read the data-price attribute of the clicked button instead. Which is more reliable?
  2. Build a fifth variable of type Custom JavaScript that returns the price as a number: function(){ return Number({{dom — plan price}}); }
  3. Build a RegEx Table that matches plan names case-insensitively.
