1.5 Getting real 30 minutes

Track a form submission

What this page is for

This page has two forms. They look identical. The Form Submission trigger works on one and does nothing at all on the other. You will find out why.

You will build:

  • A Form Submission trigger with Check Validation switched on
  • A tag that only fires on a successful submission
  • An understanding of when this trigger cannot be used

Step 1 Submit both forms

Submit Form A empty first. Then with a valid email. Then submit Form B. Watch the readouts and the dataLayer panel.

Form A — a plain HTML form

A real <form> with a real submit button.

Not submitted yet.

Form B — a JavaScript form

Not a <form> at all. The button runs a function.

Not submitted yet.

Step 2 Switch on the form variables

  1. Go to Variables › Configure.

  2. Under Forms, tick Form ID, Form Classes, Form Element and Form URL.

Step 3 Build the trigger

  1. Triggers › New › Form Submission.

  2. Tick Check Validation. A new field called Enable when appears.

  3. Fill in the whole trigger:

    Wait for TagsOn, 2000 ms
    Check ValidationOn
    Enable whenPage URL contains /gtm-course/
    Fires onSome Forms: Form ID equals newsletter-form
    NameForm — newsletter

  4. Save.

What Check Validation does

Without it, the trigger fires even when the browser rejects the form for a missing field, and you count submissions that never happened. With it on, Tag Manager waits to see whether the form was accepted.

Enable when is asking on which pages it should install its listener. Any condition that is true on this page will do.

Step 4 Build the tag and test

  1. Tags › New › Custom HTML:

    <script>
  console.log("Form submitted:", {{Form ID}});
</script>

  2. Attach the trigger. Save.

  3. Press Preview and connect to this page.

  4. Submit Form A empty. Then with a valid email. Then submit Form B.

What you should see

  • Form A, empty: a Form Submission event appears, and your tag is under Tags Not Fired. Validation failed, so the trigger correctly held back.
  • Form A, valid email: the tag fires. The console prints Form submitted: newsletter-form.
  • Form B: no Form Submission event appears at all. Instead you get a custom event called generate_lead, because this page pushes one itself.

Form B is not a configuration mistake

Form B never fires a native submit event, so the Form Submission trigger cannot see it. Changing the Form ID in your trigger will not help. Nothing you do in this trigger type will help.

This is normal on modern sites: single-page apps, most form builders, and anything using fetch(). Your options, best first:

  • Ask a developer for a dataLayer.push() on success — that is Module 2
  • Use a Custom Event trigger if the platform already pushes something
  • Use an Element Visibility trigger on the thank-you message — that is exercise 1.6

If it does not work

  • The trigger fires on the empty form too. Check Validation is not ticked, or Enable when is empty.
  • Form ID is blank. The form has no id attribute. Filter on Form Classes or Form URL instead.
  • Nothing at all on Form A. The form variables are not enabled. Go back to Step 2.
  • You are tempted to use a click trigger on the submit button. Do not. It counts every failed attempt as a conversion. If you must, name the event form_submit_attempt, not generate_lead.

Go further

  1. Add {{Form URL}} to the tag so you can tell the same form apart on different pages.
  2. Build a Custom Event trigger for generate_lead so Form B is tracked too. Compare how much work each approach was.
  3. Replace the Custom HTML tag with a real GA4 event tag named generate_lead.
