4.1 Careful now 60 minutes

Track a shop from listing to purchase

What this page is for

The shop below already pushes all six GA4 ecommerce events, correctly structured. Your job is to catch them in Tag Manager and send them to GA4.

You will build:

  • One Data Layer Variable for the whole ecommerce object
  • One Custom Event trigger using regex to catch all six events
  • One GA4 event tag that handles the entire funnel

Step 1 Run the whole funnel once

Do this before touching Tag Manager. Watch the panel as you go — every event is there in full.

  1. Press View on a product.

  2. Press Add to cart on two different products.

  3. Remove one of them.

  4. Press Start checkout, then Place order.

    Step 2 Build one variable for the whole object

    Do not build a variable per field. GA4's tag understands the whole ecommerce object at once.

    1. Variables › New › Data Layer Variable.

    2. Data Layer Variable Nameecommerce
      Data Layer VersionVersion 2
      Namedlv — ecommerce

    3. Save.

    Step 3 Build one trigger for all six events

    1. Triggers › New › Custom Event.

    2. Tick Use regex matching.

    3. Event name^(view_item_list|select_item|view_item|add_to_cart|remove_from_cart|begin_checkout|purchase)$
      Use regex matchingOn
      NameCustom Event — ecommerce

    4. Save. The ^ and $ matter — without them, purchase would also match an event called purchase_failed.

    Step 4 Build one GA4 tag for the whole funnel

    1. You need a GA4 configuration first. If you do not have one: Tags › New › Google Tag, with your G- measurement ID, on Initialization — All Pages.

    2. Tags › New › Google Analytics: GA4 Event.

    3. Measurement IDyour G-XXXXXXX
      Event Name{{Event}}
      Send Ecommerce dataOn
      Data sourceData Layer
      TriggerCustom Event — ecommerce
      NameGA4 — ecommerce (all events)

    4. Save. Preview. Run the funnel again.

    Why {{Event}} in the Event Name field

    {{Event}} is a built-in variable holding the name of the event that is firing right now. One tag then sends add_to_cart as add_to_cart and purchase as purchase. Six tags would do the same job and be six times the maintenance.

    What you should see

    • Six event names in Tag Assistant's left column as you work through the funnel.
    • Your one GA4 tag fired on every one of them.
    • On purchase, the Variables tab shows dlv — ecommerce containing transaction_id, value, tax, shipping and an items array.
    • An ecommerce: null entry in the panel immediately before every ecommerce event.
    • In GA4's Realtime report, the events appear with product names attached.

    If it does not work

    • Events arrive with no products. Send Ecommerce data is off, or Data source is not set to Data Layer.
    • The wrong product is attached. The ecommerce: null push is missing. Without it, GA4 reads leftover items from the previous event.
    • The purchase is counted twice. Reloading a thank-you page pushes purchase again. GA4 deduplicates on transaction_id — so it must be the real order number, never a random one per page load.
    • value does not match the items. On add_to_cart, value is the price of what was added. On begin_checkout and purchase it is the whole cart. Check which one you are looking at.
    • Revenue looks wrong in GA4. currency is missing, or is not a three-letter ISO code. SEK, not kr.

    Step 5 Read the code

    Open js/shop.js. Every push in it follows the same two lines:

    // 1. Clear the previous product.
dataLayer.push({ ecommerce: null });

// 2. Send the new one.
dataLayer.push({
  event: 'add_to_cart',
  ecommerce: {
    currency: 'SEK',
    value: 899,
    items: [{
      item_id:       'SKU-101',      // required
      item_name:     'Blue running shoe', // required
      item_category: 'Shoes',
      item_brand:    'Demo',
      price:         899,
      quantity:      1
    }]
  }
});

    This is the specification you hand a developer. GA4 needs either item_id or item_name on every item; everything else is optional but reports get thin without it.

    Go further

    1. Split purchase onto its own trigger and tag. Was that worth doing? Argue both sides.
    2. Add an Element Visibility trigger so view_item_list only fires when the grid is actually on screen, rather than on page load.
    3. Build a Lookup Table mapping item_category to an internal department code, and add it to the items as a custom parameter.
    4. Break it on purpose: comment out the ecommerce: null line in shop.js, add product A, then add product B. Watch what arrives.
