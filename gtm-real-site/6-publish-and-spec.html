Exercise 6 Real work About 60 minutes

Go live, and ask a developer for what is missing

What you will do

Everything you have built so far only works in Preview mode, for you. Visitors get nothing until you publish. You will publish, and then check the live shop the way anyone would see it.

Then the other half of the job. The email form at the bottom of every page does not send anything to the dataLayer. On a real site, you would write down exactly what it should send and give that to a developer. Here you will write it, and then play the developer and add the code yourself.

Step 1 Publish

  1. In Tag Manager, click the blue button Submit at the top right.

  2. Under Version Name, type Version 1 - page info, buttons, form, shop. Under Version Description, write one line for each thing you built. In a few months you will be glad you did.

  3. Click Publish at the top right.

  4. Click Versions in the menu at the top. Your version is marked as Live.

Step 2 Check it as a visitor

  1. Close the shop window that was connected to Preview mode.

  2. Open a private browser window (Ctrl + Shift + N in Chrome, Cmd + Shift + N on a Mac). Open the shop's home page in it. Click around: open a coffee, add it to the cart, send the subscribe form.

  3. Go to analytics.google.com. Click Reports in the menu on the left, then Realtime.

  4. Within a minute, your events appear in the box Event count by Event name. Click add_to_cart, then click a parameter name, to see the values that arrived.

Step 3 Write down what the missing event should look like

At the bottom of every shop page there is a form called Fresh roast news. It works, but it sends nothing to the dataLayer, so you cannot track it. This is the note you would give a developer. It has four parts: a name, when it happens, what information it carries, and an example.

Event namenewsletter_signup
WhenWhen the Fresh roast news form at the bottom of the page is sent, on any page
Informationform.id: the form's ID, footer-newsletter
form.location: where on the page, footer
user.consent.marketing: true, because the person asked for email
Example
{
  event: 'newsletter_signup',
  form: { id: 'footer-newsletter', location: 'footer' },
  user: { consent: { marketing: true } }
}

Step 4 Play the developer: add the code

  1. Open the file site.js in the site folder in your text editor.

  2. Use the editor's search (Ctrl + F or Cmd + F) to find EXERCISE 6. Just below it is this code:

    news.addEventListener('submit', function (e) {
    e.preventDefault();
    news.innerHTML = '<p class="notice">Thanks — you are on the list.</p>';
});

  3. Add the lines shown in orange, so it becomes this. Be careful with every bracket and comma.

    news.addEventListener('submit', function (e) {
    e.preventDefault();
    window.dataLayer.push({
        event: 'newsletter_signup',
        form: { id: 'footer-newsletter', location: 'footer' },
        user: { consent: { marketing: true } }
    });
    news.innerHTML = '<p class="notice">Thanks — you are on the list.</p>';
});

  4. Save the file. Upload it to GitHub the same way as in exercise 1, into the site folder. Wait two minutes.

  5. Open the shop's home page and reload it with Ctrl + Shift + R or Cmd + Shift + R. Scroll down, type an email in the Fresh roast news form, and click Sign up. Open the Developer view. The last entry is newsletter_signup.

Step 5 Play the analyst: track it

  1. Make a Custom Event trigger with event name newsletter_signup. Name it CE - newsletter_signup.

  2. Make a Data Layer Variable named dlv - form.location with Data Layer Variable Name form.location.

  3. Make a GA4 Event tag. Event Name newsletter_signup. One parameter: form_location = dlv - form.location. Event Settings Variable: GA4 - shared event settings. Trigger: CE - newsletter_signup. Name it GA4 - newsletter_signup.

  4. Test it in Preview mode: send the form, and check that the tag fired with form_location: footer.

  5. Click Submit, name the version Version 2 - newsletter form, and Publish.

What you should see

  • Two versions under Versions, and version 2 marked Live.
  • Your events in the Realtime report in Google Analytics, from a browser that is not in Preview mode.
  • newsletter_signup in Realtime, with form_location and page_type.

Preview shows your draft. Visitors see the published version.

When someone says "the tracking does not work" and you can see it working in Preview mode, the first question is: did you publish? The second question is: do they have an ad blocker?

If it does not work

  • Realtime is empty. Check that you published, that you are looking at the right property, and that the browser has no ad blocker.
  • The shop stopped working after editing site.js. A bracket or comma is missing. Compare your code with the example above, character by character. If you cannot find it, download a fresh copy of the file from the zip and try again.
  • The event shows in the Developer view but the trigger does not fire. The event name in the trigger must be exactly newsletter_signup.

You are done

You have now done the whole job, from the first line of code on the site to data in a report. This is the same work, in the same order, on every website: put the snippet in, read what the site sends, build variables, triggers and tags, publish, check, and write down what is missing.

If you get stuck, search for: gtm publish container version, ga4 realtime report.
